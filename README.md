# my-kart

**[▶ 在线打开](https://shenlu718.github.io/my-kart/)**

我的第一个 3D 网页项目。用它学会「从零到发布 GitHub」的完整流程。

## 现在能干什么

用键盘开动一个小车：车会朝车头方向前进，相机跟在车后上方。

| 操作 | 按键 |
|---|---|
| 前进 | `↑` 或 `W` |
| 后退 | `↓` 或 `S` |
| 左转 | `←` 或 `A` |
| 右转 | `→` 或 `D` |

松开按键就停。同时按住前进和后退会互相抵消（`1 - 1 = 0`），不会打架。

## 怎么跑

**双击项目里的「启动游戏.bat」** —— 服务器会起来，浏览器会自动打开游戏页面。

（第一次双击如果 Windows 弹出安全提示，选"仍要运行"。关掉那个黑窗口就停止服务。）

### 为什么不能直接双击 index.html

因为 `main.js` 用了 `import` 语法（`type="module"`），浏览器对"本地文件之间互相 import"
有安全限制，必须通过服务器访问。

### 为什么不用 `python -m http.server`

一开始用的就是它，但它有两个坑，都真实卡住过我们：

1. **缓存坑（最坑）**：它只发 `Last-Modified`、不发 `Cache-Control`。浏览器遇到这种响应
   会自己猜一个缓存期——规则是"文件多久没变，就缓存它 10% 的时间"。文件放了一天多，
   浏览器就缓存它几个小时，**这期间它连问都不问服务器一声**。结果就是：改了代码，
   浏览器却拿旧文件来跑，你看到的是旧画面，还以为是代码写错了。
2. 不会自动打开浏览器，每次都要自己去地址栏输网址。

`dev-server.mjs` 就是为解决这两件事写的：明确发送 `Cache-Control: no-store`
（每次都取最新的），启动后自动调系统默认浏览器打开页面。


## 怎么验证它是对的

**自动验证**（能跑的代码）：

```bash
cd D:/tianshu/task/webgame/my-kart
npm test
```

会跑 `src/kart-math.test.js` 里的 9 个测试，检查车的运动算得对不对
（前进距离、左右转方向、不按键就不动、帧率无关等）。

**人工验证**（必须亲眼看的）：

| 检查项 | 怎么算通过 |
|---|---|
| 画面渲染 | 看到网格地面和蓝色小车，不是黑屏也不是报错 |
| 前进 | 按住 `↑`，小车朝远离镜头的方向移动，网格向后退 |
| 转向 | 按住 `←`，小车向左转；按住 `→`，向右转 |
| 相机跟随 | 转弯时镜头始终跟在车后，不会看到车的正面 |
| 缩放不变形 | 拖动浏览器窗口大小，画面不拉伸 |

## 文件说明

| 路径 | 作用 |
|---|---|
| `index.html` | 网页骨架，把画布放上去 |
| `src/kart-math.js` | **车的运动计算**（纯函数，可以被测试） |
| `src/kart-math.test.js` | 上面那个文件的测试（9 条） |
| `src/main.js` | 3D 场景、键盘监听、把计算结果画到屏幕上 |
| `vendor/three/` | Three.js 库本体（本地副本，断网也能跑） |
| `PROGRESS.md` | 进度记录。**每次换窗口前更新它** |
| `.rivet.md` | 告诉 AI 这个项目用什么技术、有什么约定 |
| `package.json` | Node 项目的身份文件，`npm test` 命令在这里定义 |

## 为什么把逻辑拆成两个文件

`kart-math.js` 只做「输入数字 → 输出数字」，不碰浏览器也不碰 3D 库，
所以可以在 Node 里自动化测试。
`main.js` 负责「听键盘」和「画到屏幕上」，这两件事没法自动化测试。

**把能测的部分和不能测的部分分开写** —— 这是写出可靠代码的第一步，
也是这个项目里最重要的一个设计决定。

## 为什么不用 npm 装依赖 / 不用 Vite

现在刻意不装构建工具 —— **先用最原始的方式跑通，你才能体会后面为什么要引入工具**。
（`npm test` 用的是 Node 自带的测试功能，不需要装任何东西。）

等这个项目长到几十个文件、加载慢得难受的时候，我们再把 Vite 加进来，
那时你会立刻明白它解决什么问题。
